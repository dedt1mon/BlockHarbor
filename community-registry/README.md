# Каталог сборок BlockHarbor

Лаунчер использует публичный HTTPS API `/v1` по адресу из `launcher/community_catalog.py`. `worker.mjs` обслуживает каталог, D1 (`DB`) хранит метаданные и состояние загрузок, R2 (`BUCKET`) хранит архивы. Схема базы находится в `drizzle/`.

`POST /v1/uploads` резервирует публикацию. Автор получает идентификатор сессии и секретный ключ. Он загружает части по 8 МиБ через `PUT /v1/uploads/{upload}/parts/{number}` и вызывает `POST /v1/uploads/{upload}/complete`. Публикация становится видна после проверки целостности архива. Для этих операций используется заголовок `Authorization: Bearer …`. Секрет остаётся у автора.

`GET /v1/builds` возвращает страницу опубликованных сборок. Поддерживаются параметры `q`, `category`, `version`, `loader` и `offset`. `GET /v1/builds/{id}/archive` возвращает снимок. Владелец может отозвать публикацию через `DELETE /v1/builds/{id}`. Публичный ID не даёт права на изменение или удаление.

Максимальный размер **новой** публикации — 256 МиБ (старые большие архивы остаются совместимыми с механизмом скачивания до истечения TTL). Лимит суммарного объёма можно задать числом байтов в `CATALOG_STORAGE_LIMIT`. Общий жёсткий потолок каталога — 8 ГиБ (включая незавершённые резервирования); при меньшем `CATALOG_STORAGE_LIMIT` применяется он. Незавершённая сессия истекает через сутки.


## Резервный публичный канал без обязательного доступа к chatgpt.site

Публичный основной реестр остаётся источником правды для публикации и удаления сборок. GitHub Actions (`.github/workflows/community-mirror.yml`) каждые пять минут запрашивает только открытые записи, сверяет SHA-256 публичных ZIP-архивов и зеркалирует их в **GitHub Releases**, не затрагивая секреты и закрытые загрузки. Все зеркальные релизы имеют статус *prerelease* и `latest=false`, поэтому механизм обновления лаунчера их не принимает за обновления.

- `community-mirror-index/index.json` — актуальный публичный список, формат 1, отметка времени синхронизации.
- `community-mirror-00` … `community-mirror-1f` — архивы по 32 сегментам; каждый до 1000 файлов (ограничение GitHub Releases). Сегмент вычисляется из первых двух шестнадцатеричных цифр ID по модулю 32.
- Лаунчер при недоступности основного каталога (блокировка сети, 403, 5xx) автоматически использует резервный индекс и архив. Данные ограничены сроком актуальности 2 часа; снимки проверяются по размеру и SHA-256, как и при обычном скачивании.
- После снятия сборки с публикации зеркало удаляет архив при следующей успешной синхронизации. Уже скачанные другими пользователями копии отозвать невозможно. Синхронизация обычно выполняется каждые пять минут, но расписание GitHub Actions может сдвигаться.
- Публикация и снятие публикации по-прежнему выполняются на основном реестре, чтобы не создавать конкурирующие источники правды. Резервное зеркало предназначено для поиска и установки игроками.
- Доступность GitHub зависит от провайдера и региона. Не обещается абсолютная доступность из каждой сети.

См. `tools/sync_community_mirror.py` и тесты `tests/test_community_mirror.py`. Для принудительной синхронизации используйте `workflow_dispatch` workflow `Synchronize public BlockHarbor community mirror`.


## Публикации на 1 час

Новая политика после развёртывания обновлённого Worker: каждая проверенная публикация доступна **3600 секунд от момента подтверждённой загрузки**. По истечении срока она скрывается в списках и по ID. Фоновые и запрашиваемые операции очистки удаляют ZIP из R2 и запись из D1; архивы с GitHub-зеркала убираются при следующей синхронизации. Установка уже скачанных копий не затрагивается, а локальные сборки пользователей не удаляются.

Лаунчер получает `expiresAt` в компактном JSON-манифесте и никогда не устанавливает просроченную запись из зеркала. Полный ZIP и его встроенный `blockharbor.json` остаются в прежнем формате, чтобы не ломать установку пользовательских модов.

**Процедура безопасного развёртывания:** [RETENTION-ONE-HOUR.md](RETENTION-ONE-HOUR.md). Без её выполнения и проверки живого сервера изменение останется только в GitHub. Для настоящей периодической очистки R2 нужен включённый Cron Trigger (рекомендуется каждые 5 минут). Сервис сохраняет прежний жёсткий лимит общего хранилища, даже если много пользователей публикует сборки одновременно.

## Антиспам и временная блокировка публикаций

Ограничения: 256 МиБ на новую сборку, максимум 3 активных публикации с одного сетевого адреса, 10 попыток в течение 10 минут; 11-я попытка вызывает запрет новых публикаций на 5 часов. Каталог и скачивание остаются доступными. В D1 хранится HMAC от сетевого адреса, а не исходный IP. Для сервера необходимы миграция `drizzle/0001_abuse_guard.sql` и секрет `RATE_SALT`. Подробности и проверки при совместном использовании IP: [ABUSE-GUARD.md](ABUSE-GUARD.md).
