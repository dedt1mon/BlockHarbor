# Восстановление и управление дополнениями

## Что сохраняет BlockHarbor

Точка восстановления сборки включает `mods`, `resourcepacks`, `shaderpacks`,
`config`, `defaultconfigs`, игровые файлы настроек, установленную версию загрузчика,
закреплённые версии дополнений и выбранные настройки производительности. Имена,
описания и локально кэшированные изображения дополнений сохраняются при отключении,
копировании и восстановлении.

Миры сохраняются отдельными копиями. Восстановление сборки не откатывает игровой
прогресс; восстановление мира не заменяет дополнения. `session.lock` в архив не
попадает. Скопировать или восстановить мир можно после выхода из Minecraft.

Перед удалением, включением, отключением или обновлением дополнений создаётся точка
восстановления. Перед откатом текущее состояние сохраняется ещё раз. Изменение
загрузчика, ручной импорт и изменение производительности также используют этот
механизм через `before_change`.

По умолчанию остаётся до десяти копий сборки и до десяти копий каждого мира. Общий
бюджет всех копий составляет 5120 МБ. Эти пределы можно изменить в окне
«Восстановление». Самая новая копия сохраняется, даже если она одна превышает
бюджет; более старые точки удаляются по выбранной политике. Одна копия ограничена
16 ГБ и 60 000 файлами.

В **Сборки → Настройки → Миры и копии** можно включить сохранение изменённых миров после выхода из игры.
Настройка индивидуальна для каждой сборки и по умолчанию выключена. Неизменённые
миры с уже существующей копией пропускаются. Для проверки используется время
изменения `level.dat` и размер файлов мира, а не оценка прогресса внутри Minecraft.

Восстанавливаемое удаление сборки оставляет её точки восстановления. После
подтверждённого безвозвратного удаления удаляются и соответствующие копии,
закрепления, история и сохранённые параметры.

## Дополнения

Список показывает название и версию из метаданных JAR или из последней установки
Modrinth. Для неизвестных локальных файлов остаётся имя файла. Описание ресурс-пака
читается из `pack.mcmeta`. Информация извлекается из ограниченных по размеру
описаний; код дополнений не запускается.

Поиск применяется только к установленным файлам текущей категории. Можно выбрать
несколько файлов, отключить или включить их вместе либо удалить. Отключение меняет окончание имени на `.disabled`; файл остаётся
на компьютере. Встроенные компоненты Steam и передачи скинов обслуживаются
лаунчером и защищены от этих действий.

В карточке файла указаны объявленные зависимости и активные моды, которым он
нужен. Отключение обязательной библиотеки сначала открывает предупреждение.
Включение второго файла с тем же идентификатором мода блокируется. Проверка не
может обнаружить все конфликты, которые проявляются только при выполнении кода.

## Совместимость с историей версии 2.0

В версии 2.1 из списка дополнений убраны кнопки закрепления, снятия закрепления,
проверки обновлений и ручного обновления списка. Новые выпуски дополнений можно
выбирать в окне **Скачать с Modrinth**. Сохранённые закрепления и точки восстановления
версии 2.0 остаются в данных. Описанный ниже механизм обслуживания планов сохранён
для совместимости; отдельной кнопки его запуска в текущем интерфейсе нет.

Механизм не запускается при открытии списка. Файлы опознаются через API Modrinth
по SHA-512; страница списка не делает сетевых запросов. Проверяются включённые
дополнения, при выборе нескольких файлов — только выбранные кандидаты. Закреплённые
и встроенные компоненты пропускаются. Установка использует стабильные выпуски,
совместимые с версией Minecraft и загрузчиком сборки.

Сначала строится общий граф обязательных зависимостей. Затем файлы загружаются в
отдельный временный каталог, проверяются по размеру и SHA-512, и проверяются
локальные метаданные. В окне плана показаны старые и новые версии, дополнительные
зависимости, сведения об изменениях, предупреждения и конфликты. Состав сборки
меняется только после кнопки «Применить». Если файлы или закрепления успели
измениться, план требуется проверить заново.

При применении обновлений создаётся точка восстановления. Старые каталоги
сохраняются до завершения замены. Журнал позволяет восстановить исходные файлы
после прерывания процесса. Повреждённый архив, несовпавшая контрольная сумма,
путь за пределы сборки или символическая ссылка блокируют восстановление.

Документация API: [получение версий по хешам](https://docs.modrinth.com/api/operations/versionsfromhashes/),
[версии проекта](https://docs.modrinth.com/api/operations/getprojectversions/).

## Проверка реализации

Автоматические проверки покрывают независимое восстановление сборки и мира,
контрольные суммы, пути и ссылки, предупреждения зависимостей, дубликаты модов,
откат при ошибке замены, восстановление журнала после перезапуска, закрепления,
устаревший план обновлений, очистку после удаления, автоматические копии и
сохранение названий и изображений. Дополнительная проверка настоящих HTTP-маршрутов
и клиентских обработчиков выполняется на временных данных.

Проверка JavaScript в DOM не заменяет проверку расположения элементов в настоящем
окне Windows или запуск совместной игры.
