# BlockHarbor 2.6.18

## Подготовка NeoForge после передачи сборки

Выпуск исправляет цепочку подготовки NeoForge, из-за которой импортированная
сборка могла останавливаться на загрузке установщика или его зависимостей.
Предыдущая версия восстанавливала сам `installer.jar`, но Java-установщик
продолжал самостоятельно обращаться к Maven. Теперь этот второй этап тоже
проходит через подготовку BlockHarbor для поддержанного поколения установщика.

### Устойчивое получение файлов

- Оба HTTPS-транспорта обрабатывают ограниченное число перенаправлений.
  Переход с HTTPS на HTTP запрещён; проверка сертификатов сохраняется.
- При недоступности основного Maven проверенный файл может быть получен с
  резервного источника. Работающий резервный источник используется для следующих
  зависимостей в этой же подготовке, чтобы не повторять долгое ожидание на каждом
  файле. Каждая загрузка всё равно проверяется по доверенной контрольной сумме.
- Незавершённый установщик сохраняется между попытками. При поддержке сервером
  используется продолжение через Range/If-Range. Если сервер возвращает другой
  файл, неверный диапазон или полное тело вместо продолжения, данные проверяются
  и при необходимости загрузка начинается заново. Частичный JAR не запускается.
- Ограничены бюджеты попыток и общего получения файла. В ошибке видны имя файла,
  фактически проверенные серверы и результаты попыток, включая последний отказ.

### Java устанавливает заранее подготовленные файлы

BlockHarbor читает список зависимостей из официального установщика, проверяет
их пути, версии, размеры и SHA1, получает их своими транспортами и сохраняет
проверенные файлы. Оригинальный установщик остаётся неизменённым.

Для проверенного SimpleInstaller 3.0.48 с поддерживаемым набором процессоров,
включая NeoForge **21.1.267 для Minecraft 1.21.1**, установка запускается со
штатным `--offline`. Официальные mappings Minecraft подаются как локальный
ресурс, который сам установщик умеет использовать. Это устраняет отдельную
сетевую загрузку внутри Java на данном пути.

Для других поколений установщиков BlockHarbor заранее готовит проверяемые
библиотеки, но сохраняет исходный режим Java: неподдерживаемый автономный режим
не включается по предположению. Этапы проверки, скачивания зависимостей и локальной
установки видны в панели справа внизу.

Готовые файлы Minecraft и Java проверяются локально. Если NeoForge нужна копия
того же клиента под своим идентификатором, она создаётся из проверенного базового
JAR. Повторное получение одинаковых байтов и обязательный новый запрос каталога
Java для уже подготовленных файлов устранены.

### Проверенные файлы NeoForge в ZIP

**Сборки → Выгрузить** автоматически включает доступный проверенный установщик
NeoForge и сохранённые библиотеки его подготовки. Для давно установленной
сборки, у которой установщика в кеше ещё нет, лаунчер сначала пытается получить
её точную закреплённую версию. Новая версия загрузчика вместо неё не выбирается.

В результате выгрузки указано, были ли файлы NeoForge включены в архив. Если
получить установщик не удалось или сборка ещё не подготовлена, обычная выгрузка
остаётся доступной, а уведомление объясняет, что загрузчик потребуется получить
при первом запуске.

На компьютере друга файлы сначала сохраняются внутри нового экземпляра сборки.
Перед использованием BlockHarbor независимо проверяет официальный установщик,
затем сверяет библиотеки с его собственным списком. Контрольные суммы,
присланные только автором ZIP, не разрешают запуск неподтверждённых файлов.
Профиль готовой установки и её отметка об успехе с чужого компьютера не копируются.

В этот перенос не входят Java, клиент Minecraft, ресурсы и библиотеки Mojang,
сгенерированный игровой JAR, данные входа или личные настройки. На полностью
чистом компьютере их подготовка по-прежнему требует официальных загрузок.
Это ZIP с файлами подготовки NeoForge, а не обещание полностью автономного
Minecraft. Quick Skin сохраняет прежний способ получения из официального источника.

### Как передать сборку после обновления

1. Обнови BlockHarbor до **2.6.18** у себя и у друзей.
2. Открой **Сборки → Выгрузить** у нужной подготовленной сборки и дождись ZIP.
3. Проверь уведомление: для переноса файлов NeoForge должно быть указано,
   что они включены. Передай новый ZIP другу обычным удобным способом.
4. Друг открывает **Сборки → Загрузить сборку**, выбирает ZIP и нажимает **Играть**.

Старые обычные ZIP поддерживаются и используют улучшенную загрузку. Для архива
нового формата с файлами NeoForge требуется 2.6.18 или новее. Уже импортированную
сборку можно сначала просто запустить после обновления: проверенные файлы и
незавершённый установщик переиспользуются, всю папку данных удалять не нужно.

### Проверка выпуска

Перед публикацией Windows-пакет проходит установку и обновление в отдельном
каталоге, запуск встроенного Python и локального API, проверку скачивания
настоящего установщика с основного и резервного источников, полную подготовку
Minecraft 1.21.1/NeoForge 21.1.267 с принудительно недоступным основным Maven,
передачу настоящего ZIP в другое хранилище и локальное повторное использование.
Проверка не запускает игровой сеанс и не подменяет проверку конкретного набора модов
или соединения с друзьями.

Функция **Поделиться** остаётся временно отключённой. Используется существующая
выгрузка и загрузка ZIP, без нового окна подтверждения.
