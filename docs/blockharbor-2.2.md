# BlockHarbor 2.2: запуск, закрытие и автоматическое обновление

## Сообщение о старой версии

В 2.0 после закрытия браузерного окна Python-процесс мог ещё до 180 секунд
удерживать блокировку общей папки. 2.1 проверял её сразу и выдавал отказ запуска.
Кроме того, Windows-ошибка доступа к файлу могла интерпретироваться как занятая
блокировка. Эти причины исправлены независимо.

Новая версия ждёт завершения настоящего старого сеанса. В Windows появляется
небольшое окно с причиной ожидания и кнопкой **Отмена**; крестик также отменяет
запуск. При освобождении блокировки лаунчер открывается автоматически. Для
перехода с 2.0 предусмотрено ожидание до 190 секунд. Запущенную старую версию
нужно закрыть. Реальные ошибки доступа показываются как ошибки доступа.

Лаунчер не удаляет занятый файл блокировки, не завершает чужие процессы и не
считает старый PID в файле доказательством работающего приложения. Решение
принимается по системной блокировке. Файл, оставшийся после аварии, сам по себе
не мешает запуску. Несколько окон 2.1/2.2 по-прежнему согласуют изменения сборок.

## Настройка обновления

Открой **Настройки → Загрузки и обновления** и включи
**Автоматически обновлять BlockHarbor**. Переключатель сохраняет состояние сразу.

1. При открытии приложения и каждые 10 минут сеанса проверяется выбранный канал GitHub.
2. Совместимый новый установщик скачивается и проверяется по размеру и SHA-256.
3. Установка ожидает завершения игр, загрузок и операций, а также закрытия других окон.
4. Проверенный установщик обновляет существующую папку, затем открывается одно окно новой версии.

Можно отложить готовую автоустановку до следующего запуска или выключить
переключатель. Ручные действия остаются доступны. При миграции учитывается
выключенная в старой версии проверка при запуске. Неудачный выпуск автоматически
не переустанавливается бесконечно: доступен ручной повтор. Несовместимая схема
данных или неподтверждённый хеш блокируют установку.

Первый переход на 2.2 требует нового установщика или старой кнопки обновления.
Уже установленная версия не получает новую логику до этого перехода.

## Что означает закрытие

| Действие | Результат |
| --- | --- |
| Крестик окна / закрытие вкладки лаунчера | Отмена операций этого окна, проверки обновлений, подготовки и ожидающей установки; завершение принадлежащих ему служебных процессов |
| Сворачивание | Сеанс продолжает работать |
| Автоматическое скрытие при старте Minecraft | Лаунчер ждёт выхода своей игры и затем возвращает окно |
| Обновление страницы | Остаётся текущий сеанс; новый page lease заменяет прежний |
| Успешная автоматическая установка | Короткая передача управления установщику и один повторный запуск |

Закрытие одного окна не закрывает другие окна BlockHarbor. Уже запущенный
Minecraft сохраняет собственный процесс; принудительное завершение игры могло
бы потерять несохранённый мир. Лаунчер не запускается в фоне при входе в Windows
и не устанавливает службу, Run/RunOnce или задачу планировщика.

В режиме Microsoft через Prism после передачи запуска открытый Prism является
отдельным приложением. BlockHarbor отменяет собственную подготовку и наблюдение,
но не завершает общий Prism, который может обслуживать другое окно или игру.
Если Prism ещё показывает вход или скачивание, его окно закрывается отдельно.

Версии до 2.1 не знают реестр игровых сеансов нового лаунчера. Не запускай
старый 2.0 рядом с оставленной работающей игрой 2.2. В актуальных версиях занятая
сборка и установщик проверяют зарегистрированные игровые процессы.

## Проверка реализации

Перед выпуском пройдён общий набор из **381 Python-теста**, включая два запуска
настоящего backend-процесса с закрытием через HTTP. Пройдены также **7 сценариев
интерфейса настройки обновления** с локальным API и **6 сценариев событий окна**
в JavaScript.

Тесты охватывают реальные межпроцессные блокировки, освобождение после аварии,
отмену ожидания, ошибки Win32, закрытие во время загрузки/подготовки и сохранность
установленных файлов при отмене. Проверяются публикация сборки после подготовки,
резервные копии, обновление страницы, сворачивание, двухфазная передача помощнику,
каналы, проверка хеша, отказ от автоматических обновлений и восстановление после
ошибки установщика. Нативные Win32-окна, NSIS и живая игра требуют отдельной
проверки на Windows; Linux-тесты не заменяют такой запуск.

Подробности источника и обновления: [обновления и загрузки](updates-and-downloads.md).
