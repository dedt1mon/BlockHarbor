# Статус сеанса Minecraft в BlockHarbor

BlockHarbor включает небольшой собственный мод **BlockHarbor Room Status**.
Он читает публичный Addon API e4steam и сохраняет фактическую стадию текущего
сеанса, число удалённых участников и их игровые имена для внутренних проверок.
Начиная с 2.4.1 панель ручного просмотра этого статуса удалена из Друзей вместе
с блоком обмена составом сборки.

## Поддерживаемый путь

Автоматическая установка ограничена Fabric/Quilt и комбинациями Minecraft,
поддержанными закреплённым в лаунчере e4steam **0.3.6**. Сам мод использует
Addon API **1.1.0**, запрашивая две возможности:

- `session.observe` — текущий сеанс и только подтверждённые участники;
- `identity.minecraft.read` — безопасные игровые имена этих участников.

Данные берутся из `SessionService.snapshot()`, `SessionService.peers()` и
`IdentityService.remote()`. Права Steam, билеты авторизации, приглашения,
Steam ID и пароли не читаются. Аддон не открывает порт, не запускает локальный
HTTP-сервер и не получает основной ключ API лаунчера. В нём нет командного
канала для управления Minecraft.

В Forge/NeoForge текущий компонент не устанавливается. Для этих сборок
внутренний источник статуса использует последний сигнал из журнала с явным
указанием источника, а не живой список участников.

## Как исключается устаревший статус

Перед каждым запуском лаунчер создаёт случайный идентификатор запуска в
`.blockharbor-room/request.json` и удаляет предыдущий `status.json`. Аддон
публикует небольшой JSON атомарной заменой файла примерно каждые две секунды,
добавляя этот идентификатор, счётчик последовательности и время измерения.

Лаунчер принимает данные только когда именно эта сборка запущена, идентификатор
совпадает, формат и размеры полей корректны, а измерению не больше восьми секунд.
После выхода из Minecraft живые участники не показываются. После закрытия
сеанса список очищается. Неожиданные файлы, ссылки и некорректный JSON
игнорируются. Ограничение файла — 32 КБ, имён — 64 на снимок.

Дополнительно в снимке есть фактические `heapUsed`/`heapMax` JVM. Это данные
памяти Minecraft, а не оценка FPS. Частота кадров и время кадра этим компонентом
не измеряются.

## Воспроизводимая сборка

Исходник: `bridge/src/blockharbor/bridge/RoomStatusAddon.java`.
Метаданные Fabric: `bridge/fabric.mod.json`.
Готовый мод: `bundled/bridge/blockharbor-room-status.jar`.

Нужны JDK с модулем `jdk.compiler` и официальный compile-only API:

```text
https://repo.maven.apache.org/maven2/io/github/kamilhik/e4steam-api/1.1.0/e4steam-api-1.1.0.jar
SHA-256: 33f3216bbc92d5761fc4063f102110f18a9ba8a8de8096adb0fe4284835c91c4
```

```bash
python tools/build_room_bridge.py --api /path/e4steam-api-1.1.0.jar --java /path/jdk/bin/java --test
```

Скрипт проверяет хеш API, компилирует Java 8 bytecode и создаёт ZIP с фиксированными
порядком, правами и временем файлов. API e4steam в мод не вшивается: его классы
предоставляет установленный e4steam. После изменения исходника нужно обновить
`SIZE` и `SHA512` в `launcher/room_bridge.py` на значения, напечатанные сборщиком.

`bridge/test/blockharbor/bridge/RoomStatusHarness.java` проверяет связывание с
реальным API 1.1.0, обработку подтверждённых имён, смену состояния сеанса,
корректность JSON и остановку фонового работника при закрытии ресурса.
Python-проверки находятся в `tests/test_room_bridge.py`.

Эти автоматические проверки не заменяют проверку двумя настоящими аккаунтами
Steam на Windows. Полный сеанс с двумя клиентами здесь не заявляется как
пройденный. Открытие мира и отправка Steam-приглашения остаются в Minecraft:
документированный API наблюдения не предоставляет внешнему лаунчеру команду
открыть одиночный мир.

Источник контракта: [e4steam Addon API](https://github.com/Kamilhik/e4steam/blob/v0.3.6/docs/ADDON_API.md).
