# Компоненты и поведение интерфейса BlockHarbor

Этот документ описывает существующий интерфейс и дополнения ветки аудита. Он не является заявлением о прохождении проверок: фактические результаты сохраняет `tools/smoke_ui_browser.py` в `report.json`.

## Общая основа

В `ui/style.css` находятся параметры цвета, типографики, размеров и состояний. Дополнительные CSS-файлы задают компоновку своих экранов и используют общие параметры. Новый экран должен подключаться к существующему `index.html`, а не копировать отдельную тему.

| Назначение | Общий параметр / компонент |
| --- | --- |
| Основное поле и кнопка | `--control-height: 44px`, `.field`, `.btn` |
| Компактное действие в списке | `--control-compact: 36px` |
| Скругление элемента управления | `--control-radius: 9px` |
| Скругление панели | `--surface-radius: 12px` |
| Выбранный элемент | `--selection-fill`, `--selection-border` |
| Клавиатурный фокус | `--focus-ring`, `:focus-visible` |
| Обычный чекбокс | `--checkbox-size: 17px` |
| Переключатель | `--switch-width: 40px`, `--switch-height: 24px`, общие размер и смещение бегунка |
| Основные интервалы | `--space-2`, `--space-3`, `--space-4` |
| Полоса прокрутки | `--scrollbar-thumb`, тонкая полоса, одинаковое закругление |

Ввод текста использует внутреннюю границу фокуса и сохраняет размер. Иконки поступают из общей функции `ic()`. Кнопки используют `.btn`, компактные действия явно выбирают компактный размер. Нативный `title` используется для коротких подсказок; существенная информация всегда видна в тексте или доступном имени элемента.

`[hidden]` всегда скрывает элемент, даже если компонент использует `display: flex` или `display: grid`. Для взаимодействующих элементов нужны `type="button"`, доступное имя и понятное состояние `disabled`, `aria-pressed` или `aria-busy` по назначению. Переключатель использует `role="switch"`.

## Компоновка и прокрутка

Главная область занимает всё место справа от боковой панели. `minmax(0, 1fr)` и `min-width: 0` позволяют длинному тексту переноситься внутри компонента. Основная область резервирует место для полосы прокрутки, поэтому короткая и длинная страницы не меняют доступную ширину.

Общая функция `modal()` использует один нативный `dialog` с `aria-labelledby`. Заголовок и закрытие остаются вне прокручиваемого `#dialogBody`. При смене содержимого прокрутка тела сбрасывается. Высота ограничена видимой областью окна; маленькое содержимое использует собственную высоту.

Длинные имена и пути без пробелов переносятся внутри диалога. Сообщение о текущей операции занимает отдельное место под его содержимым: оно не перекрывает подтверждение или отмену при малой высоте окна. Вне модалки это сообщение остаётся компактным уведомлением в углу.

Каталоги имеют собственную область прокрутки и устойчивую высоту результатов. Контекст сборки в узкой строке сокращается визуально, полное значение остаётся в подсказке. У карточек фиксированное место под изображение и ограниченное число строк краткого описания. Полное описание доступно в подробностях проекта. При поиске и смене фильтра предыдущие результаты сохраняются до нового ответа. Фильтры каталога сборок применяются и к модпакам, и к публикациям игроков.

В низком окне каталоги переключаются на прокрутку всего тела диалога: фильтры и кнопка выбранных дополнений не могут уменьшить список результатов до недоступной полосы. Основная кнопка закрытия остаётся в заголовке.

## Настройки

`.settings-grid` размещает «Запуск Minecraft» и «Оформление» рядом, когда для каждой карточки остаётся достаточно ширины. В узком окне карточки переходят в одну колонку. `.settings-card` сохраняет общий верхний край заголовков и выравнивает действия сохранения по низу карточек. В разделе загрузок та же сетка объединяет автоматическое обновление и выбор канала; состояние выпуска и очередь файлов занимают полную ширину.

Текст описаний внутри `#settingsPanel` использует внутреннюю ширину своей панели без общего ограничения `80ch`. Поля занимают доступную ширину, включая выбор канала обновлений на узком экране.

В браузерах с `appearance: base-select` общий стиль `select.field` явно сохраняет flex-компоновку и центрирует выбранное значение по вертикали. Правило блочного поля внутри `label` не должно заменять эту внутреннюю компоновку. Высота строки остаётся относительной, поэтому обычные и компактные списки сохраняют свою геометрию. Открытый picker, клавиатурное управление, обычный нативный fallback и forced-colors сохраняются.

## Массовая установка

`ui/batch-install.js` содержит `BatchUI`, общий компонент отображения серверной операции каталога. Он получает `job.kind === "catalog-install"`, `profileId`, `items` и `reviews`. Клиент не вычисляет совместимость и не объявляет успешную установку по завершению скачивания: состояния задаёт сервер.

Поддерживаются `queued`, `checking`, `dependencies`, `downloading`, `installing`, `installed`, `already_installed`, `incompatible`, `error`, `cancelled`, `needs_review`. Общий индикатор показывает число обработанных выбранных объектов, а не выдуманный процент скачанных байтов. Счётчики вычисляются из отображаемых строк.

Компонент хранит только последний снимок операции, максимум 32 выбранных объекта. Обновления текста не заменяют весь список и не сбрасывают прокрутку. Диалог можно свернуть и открыть из постоянной кнопки в шапке. Ошибка выводится у соответствующего объекта. При частичной ошибке предварительной проверки в операцию передаётся весь выбор, чтобы сбой не исчезал из итоговых счётчиков. Повторное действие содержит только выбранные неустановленные объекты; источник проекта сохраняется.

При высоте окна до 560 CSS-пикселей заголовок и сводка используют компактные интервалы, контекст сборки занимает одну строку с полной подсказкой, а список сохраняет место для целого объекта со статусом. Кнопки в этом режиме прокручиваются вместе с телом и не накрывают первую строку. Длинное название в строке ограничено двумя строками; полное значение доступно в подсказке.

Предупреждение о совместимости требует отдельного действия «Установить с предупреждением» с конкретным токеном проверки. Клиент не подтверждает предупреждения автоматически. Отмена вызывает отдельное серверное действие и отображает подтверждённые сервером итоговые состояния.

## Уведомления и публикации

Красная точка колокольчика расположена абсолютно внутри фиксированного элемента. Она не меняет размеры шапки. Доступное имя колокольчика включает число непрочитанных уведомлений.

История сначала получает снимок сообщений, отображает его и подтверждает только `throughId` этого снимка. Более новое событие, пришедшее одновременно с открытием истории, остаётся непрочитанным. Кнопка «Показать новые» загружает следующий снимок. Состояние прочтения хранит сервер приложения в SQLite; браузер не заменяет его собственным списком прочитанных сообщений.

Обновления `/api/state` и `/api/job` используют общий порядок применения ответов и поколение принятой операции. Устаревший ответ не меняет текущую операцию или её уведомления. После полного обновления страницы observers получают актуальный `state.job`; счётчик в нём согласуется с более поздним счётчиком полного состояния. Независимая защита истории не позволяет запоздалому подтверждению прочтения погасить новое событие.

Новая публикация сборки недоступна, пока сервер не подтвердит политику хранения и ограничения через `communityCapabilities.enabled`. Ошибка проверки показывает повторное действие. Управление ранее опубликованными сборками остаётся доступным. Эта UI-проверка дополняет обязательную серверную проверку и не заменяет её.

## Проверка

`tools/smoke_ui_layout.py` проверяет представительные элементы в настоящем Chromium через Playwright, дожидаясь результата проверок в самом документе. `tools/smoke_ui_browser.py` использует те же браузерные средства, производственные HTML/CSS/JavaScript и детерминированные ответы локального API. Для обоих сценариев нужен установленный Chromium и тестовая зависимость Playwright; в runtime приложения она не входит.

Матрица: 1280×720, 1366×768, 1920×1080, 2560×1440, 3440×1440, 3840×2160 при коэффициентах 1, 1.25, 1.5, 2. Размер CSS-области равен физическому разрешению, делённому на коэффициент; `devicePixelRatio` проверяется отдельно. Сохраняются снимки экрана и JSON-отчёт.

Для настроек дополнительно проверяются широкая область 1920×1080 при 100% и узкая область 1280×720 при 200%, в каждой — масштабы текста приложения 100%, 85% и 120%. Сценарий проверяет две карточки, доступную ширину описаний, автоматическое и ручное значение памяти, длинное имя профиля запуска, Client ID, масштаб текста и канал обновлений. Открытые списки должны показывать первый и последний вариант без обрезания; Escape сохраняет выбранное значение.

Положение текста измеряется по фактическим текстовым фрагментам дерева раскладки Chromium, включая внутренние узлы элементов управления. Проверяются полнота значения, границы поля, место для стрелки, обрезающие предки и отклонение центра не более 2 CSS px. Одних размеров внешней рамки для этой проверки недостаточно. Перед каждым масштабом тест загружает новый документ и ждёт применения настроек через штатный API; визуальные проверки не сохраняют пользовательские настройки.

Дополнительно проверяются навигация, переполнение, внутренние списки больших диалогов, 32 объекта установки, повтор после ошибки, отмена, явное подтверждение предупреждения, непрочитанное событие во время открытия истории, повторное открытие страницы, подтверждение политики публикации и передача фильтров обоим источникам каталога сборок.

Проверка списка установки требует, чтобы первая строка вместе со статусом полностью помещалась в фактически видимую область с учётом всех прокручиваемых предков и закреплённых кнопок. Наличие `overflow` само по себе не считается доказательством читаемости. Для подробных сценариев сохраняются отдельные кадры частичного результата и отмены во время сообщения о текущей операции.

Эти проверки подтверждают поведение браузерного интерфейса с заданными API-ответами. Они не подтверждают установку и запуск Minecraft, доступность внешних серверов или реальное переключение системного масштаба Windows. Для таких выводов нужны отдельные интеграционные и пользовательские проверки.
