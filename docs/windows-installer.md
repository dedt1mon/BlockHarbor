# Установщик BlockHarbor для Windows

Установщик рассчитан на Windows x64 и устанавливает приложение для текущего пользователя. По умолчанию программа находится в `%LOCALAPPDATA%\Programs\BlockHarbor`, а её данные — в отдельной папке `%LOCALAPPDATA%\BlockHarbor`.

## Ярлыки и закрепление

На странице «Ярлыки и закрепление» доступны три независимые настройки:

| Настройка | По умолчанию | Действие мастера |
| --- | --- | --- |
| Создать ярлык на рабочем столе | Включена при первой установке; при обновлении сохраняется предыдущий выбор | Создаёт ярлык на установленный `BlockHarbor.exe` |
| Помочь закрепить на панели задач | Выключена | После установки показывает инструкцию для панели задач |
| Помочь закрепить в меню «Пуск» (начальный экран) | Выключена | После установки показывает инструкцию для закреплённой области меню «Пуск» |

Приложение также появляется в общем списке приложений меню «Пуск». Эта запись сама по себе не закрепляет его в меню «Пуск» или на панели задач.

Если выбрана хотя бы одна настройка помощи, после успешной установки мастер показывает дополнительную страницу. Она предлагает нажать клавишу **Win**, найти **BlockHarbor**, щёлкнуть найденное приложение правой кнопкой мыши и выбрать нужную команду Windows. Кнопка **«Показать ярлык BlockHarbor в Проводнике»** открывает папку меню «Пуск» и выделяет созданный ярлык. Он указывает на установленный лаунчер, а не на временную копию установщика.

Начиная с 2.2, автоматическое обновление использует `/S /AUTOUPDATE /D=<прежняя папка>`. Оно заменяет приложение без мастера и сохраняет существующие ярлыки, включая ручной отказ от ярлыка рабочего стола. После успешной установки помощник открывает одно окно BlockHarbor. Обычная ручная установка сохраняет выбор ярлыков в мастере.

Мастер не выполняет закрепление автоматически и не показывает неподтверждённый статус «Закреплено». Выбор помощи действует только для текущей установки. Пользователь может завершить мастер, не выполняя закрепление. При тихой установке (`/S`) эти страницы и Проводник не открываются.

### Почему закрепление выбирается в Windows

[Документация Microsoft для TaskbarManager](https://learn.microsoft.com/en-us/windows/apps/develop/windows-integration/pin-to-taskbar) прямо предписывает не вызывать API запроса закрепления из установщиков. Поддержка этого API у настольных приложений зависит от версии Windows и доступности возможностей; утверждение, что закрепление через API невозможно для всех Win32-приложений, было бы неверным. В частности, Microsoft описывает снятие требования Limited Access Feature на новых сборках Windows 11 начиная с KB5074105.

Этот NSIS-мастер предлагает стандартные действия пользователя из инструкций Microsoft:

- [Закрепление приложения на панели задач](https://support.microsoft.com/ru-ru/windows/experience/personalization/customize-the-taskbar-in-windows).
- [Закрепление приложения в меню «Пуск»](https://support.microsoft.com/ru-ru/windows/experience/personalization/customize-the-windows-start-menu).

Мастер не меняет системные списки закреплений через реестр, не применяет корпоративные политики макета и не вызывает скрытые команды оболочки для принудительного закрепления.

## Обновление и удаление

При обновлении мастер использует прежнюю папку установки и просит закрыть работающий BlockHarbor. Проверка учитывает и запущенные переносимые версии, использующие общую папку данных. Программа заменяется только после полной записи временного файла в ту же папку; если Windows блокирует замену, прежний исполняемый файл остаётся на месте.

Удаление доступно через список установленных приложений Windows или ярлык «Удалить BlockHarbor». Оно удаляет исполняемые файлы приложения, созданные мастером ярлыки и принадлежащие установке записи реестра. Начиная с 2.3 мастер предлагает два варианта: удалить только приложение или приложение вместе со всеми его локальными данными. По умолчанию данные в `%LOCALAPPDATA%\BlockHarbor` сохраняются. Полная очистка удаляет сборки, миры, копии, снимки, скины, настройки, локальные данные интеграции Prism, кэши и компоненты. Операция требует завершения игр и всех окон лаунчера; ссылки удаляются без обхода внешних целей. Тихое удаление всегда сохраняет данные.

Обычно права администратора не нужны. Если пользователь вручную запустил мастер с повышенными правами, кнопка завершения не запускает лаунчер в этом контексте: мастер предлагает открыть его обычным способом через меню «Пуск».

## Проверка выпуска

При сборке проверяются целостность встроенного пакета лаунчера, архитектура x64 и успешная компиляция NSIS. Из готового EXE можно извлечь встроенный лаунчер и сверить его байты с исходным файлом; отдельно проверяются ресурсы иконок и манифест `asInvoker` установщика и программы удаления.

Компиляция и разбор EXE не заменяют проверку поведения интерфейса на Windows. Для текущих изменений такой прогон на настоящей Windows не выполнен. При проверке на Windows 11 нужно пройти следующие сценарии:

1. Первая установка с настройками по умолчанию: появляется ярлык рабочего стола и запись в списке приложений «Пуск», страница помощи в закреплении пропускается.
2. Выбор только помощи для панели задач, только для «Пуск» и обеих опций: после установки видны только соответствующие инструкции; кнопка Проводника выделяет правильный `BlockHarbor.lnk`. Само открытие этой страницы и кнопки ничего не закрепляет.
3. Возврат к предыдущей странице до начала установки: выбранные галочки сохраняются. Отключение обеих опций помощи снова убирает дополнительную страницу после установки.
4. Закрепление через поиск Windows: закреплённый ярлык запускает установленный `BlockHarbor.exe` с правильной иконкой. После завершения лаунчера повторный запуск также работает.
5. Обновление существующей установки с выключенным ярлыком рабочего стола: выбор сохраняется, ранее созданные сборки и миры доступны. Новые опции помощи по умолчанию выключены.
6. Обновление при работающем лаунчере: мастер предлагает закрыть его и повторить попытку, не завершает процесс принудительно и не портит прежний EXE.
7. Тихая установка и удаление: не открываются страницы помощи и Проводник; после удаления игровые данные остаются на месте.
8. Полное удаление: после явного выбора стандартная папка данных очищается; активная игра блокирует очистку, внешняя цель junction остаётся нетронутой, ошибка удаления показывается пользователю.
9. Установка из вручную повышенного процесса: финишная опция не запускает лаунчер с правами администратора.

Встроенный интерфейс лаунчера использует отдельный браузерный процесс. Объединение его работающего окна с закреплённой иконкой зависит от идентификации приложения Windows и требует отдельной проверки; мастер предлагает закреплять именно найденный **BlockHarbor**, а не значок браузера.
