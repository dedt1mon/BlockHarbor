# BlockHarbor 2.6.5 — публикации, ограничения и совместимость каталога

## Изменения в лаунчере

- Ограничение размера **новых публичных ZIP до 256 МиБ** проверяется до загрузки, без изменения допустимого размера ранее опубликованных архивов.
- Окно «Поделиться» показывает статус поддержки сервером новых правил, чтобы не обещать автоматическое удаление, если действующий backend ещё не обновлён.
- Когда backend поддерживает новую версию протокола, рядом с публикацией показывается время окончания **через 1 час**, а при превышении лимита попыток открывается понятное модальное предупреждение с оставшимся временем блокировки.
- Сохранена совместимость со старыми записями без `expiresAt` и старым индексом GitHub-зеркала: поиск и скачивание без VPN не должны ломаться только из-за отсутствия нового поля. SHA-256 архивов продолжает проверяться.
- Личные файлы, локальные сборки, ранее установленные модпаки и другие функции лаунчера не затрагиваются. P2P не используется.

## Подготовленная серверная реализация

Код serverless-каталога поддерживает:
- срок опубликованного архива — 1 час после подтверждённой загрузки;
- отмену незавершённых загрузок через 30 минут;
- максимум 3 активные публикации на сетевой адрес и 256 МиБ на архив;
- максимум 10 попыток за 10 минут, 11-я вызывает ограничение **только публикаций на 5 часов**;
- глобальный верхний предел 8 ГиБ (или более строгую настройку), очистку R2/D1 и GitHub-зеркала;
- HMAC сетевого адреса с серверным секретом, без хранения IP в открытом виде;
- явный API `GET /v1/capabilities` для определения реально действующей политики.

**Важное ограничение выпуска:** обновление Windows-лаунчера **не разворачивает сервер**. Пока действующий каталог по адресу `blockharbor-community-catalog.ded8timon.chatgpt.site` работает на старом коде, на нём **не действуют** часовая очистка, серверный лимит 3 публикаций и 5-часовая блокировка. Лаунчер честно отображает этот статус. Локальный предел размера 256 МиБ действует уже в 2.6.5.

Чтобы включить всё перечисленное, администратор существующего каталога должен сохранить данные D1/R2, применить `community-registry/drizzle/0001_abuse_guard.sql`, создать серверный секрет `RATE_SALT`, обновить `worker.mjs` и включить Cron Trigger каждые пять минут. Подробности: `community-registry/ABUSE-GUARD.md` и `community-registry/RETENTION-ONE-HOUR.md`.

Заявление о работе серверной защиты допустимо **только после проверки на живом сервисе**. При общем IP или CGNAT разные игроки могут разделять квоту публикаций; это необходимо проверить перед активацией.

Установка для Windows x64: `BlockHarbor-Setup-2.6.5.exe`. Стабильный канал обновления использует `BlockHarbor-update.json` с SHA-256.
